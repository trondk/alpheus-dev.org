# alpheus-dev.org

The website for Alpheus, built with Hugo. The requirements are in
[`SPEC.md`](SPEC.md). The code is in its own repository,
[alpheus](https://github.com/trondk/alpheus).

The documentation pages live in `docs/` in the code repository, so code
and documentation change together (WWW-22). Fetch them before you build:

```sh
ci/fetch-docs.sh ../alpheus   # from a checkout next to this one
ci/fetch-docs.sh              # or clone params.repo at main (REF=v0.1.0 for a tag)
hugo server                   # preview on http://localhost:1313/
hugo --gc --minify            # build to public/
```

Or all in one: `./localwww.sh` serves the site on
http://localhost:1313/ with the pinned Hugo, which it downloads to
`.cache/` the first time, and fetches the docs from `../alpheus` again
whenever they change there.

Hugo is pinned to v0.168.0 (WWW-21).

| What | Where |
|---|---|
| Project phase shown on the front page (WWW-8) | `params.phase` in `hugo.toml` |
| Primary repository on Forgejo, used for go-import and every link to the code (WWW-19) | `params.repo` in `hugo.toml` |
| Public Go packages (WWW-17) | `data/gopackages.toml`, generated in CI |
| Front page text | `content/_index.md` |
| Text for each phase | `data/phases.toml` |

| Development and testing page | `content/development.md` |
| Documentation: getting started, writing components, comparison, ETL walk-through, verifying a release | `docs/` in the code repository, fetched into `content/docs/` |
| CLI reference, generated by `make generate` in the code repository (WWW-4) | `docs/cli.md` there |
| Theme: layouts, CSS, fonts, river | `themes/alpheus/` |

Fonts are under the SIL Open Font License; the license texts are next to
them in `themes/alpheus/static/fonts/`.

## CI

`.forgejo/workflows/site.yml` fetches the documentation, builds the site
on Forgejo Actions, checks it and publishes it with rsync to the project's web server. It expects to
be at the root of `alpheus-dev/alpheus-dev.org` on Forgejo. The GitHub
mirror ignores `.forgejo/` and runs nothing. The secrets and variables it
needs are listed at the top of the workflow.

| Check | Requirement | Run locally |
|---|---|---|
| Colour contrast of the palette | WWW-9, WWW-41 | `python3 ci/check_contrast.py` |
| No external resources, front page under 150 KB | WWW-25, WWW-26 | `python3 ci/check_site.py` (after `hugo`) |
| axe on the front page, privacy page and `/alpheus/` | WWW-34 | `npx pa11y-ci@4.1.1 --config ci/pa11yci.json` (serve `public/` on port 8080) |
| Lighthouse, at least 95 | WWW-27 | `npx @lhci/cli@0.15.1 autorun --config=ci/lighthouserc.json` |
| Vanity pages answer `?go-get=1` | WWW-17 | after deploy only |
| `go list` straight from the site | WWW-20 | after deploy, once the variable `GO_MODULE_PUBLISHED` is `true` |
